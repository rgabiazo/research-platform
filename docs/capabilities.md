# Public-alpha capability and support matrix

This page is the source of truth for what the public alpha can run, what it can
only plan or validate, and what still depends on user or site infrastructure.
Directory presence alone is not evidence that a workflow is supported.

## Status definitions

- **Runnable locally:** checked-in public inputs and configuration, documented
  commands, and an executable local verification all exist.
- **Plan/validation only:** the surface validates configuration or renders
  commands and manifests, but this public repository does not supply everything
  needed to execute the workflow.
- **Experimental or external-runtime:** implementation and automated tests
  exist, but execution needs external software, user data, site configuration,
  or still lacks a checked-in public project-level happy path.
- **Scaffold only:** placeholder structure exists without a supported runtime
  contract.

## Verified installation boundary

The supported and CI-tested interpreter boundary is Python 3.11 and 3.12. The
public-alpha CI gate verifies a clean `minimal` source installation on Ubuntu
24.04 x86_64 with both versions and on macOS 15 ARM64 with Python 3.12. The
read-only installation checks include
`bash ops/envs/dev/smoke-check.sh --venv "$VIRTUAL_ENV"`, `python -m pip check`,
and `rp --version`. The durable contracts are covered by
`ops/tests/test_bootstrap.py`, `ops/tests/test_install_smoke.py`,
`ops/tests/test_distribution_versions.py`, and `ops/tests/test_ci_contract.py`.
The checked-in deterministic `project-pilot-tabular` example also exercises
the 24-row synthetic `toy_features.tsv` path.

That evidence does **not** verify Python 3.13 or newer, another operating system
or architecture, the complete optional `full` profile, offline HPC
installation, a live cluster, or an external neuroimaging runtime. The full
profile remains subject to later full-profile release validation. Start with the
[source-checkout quickstart](onboarding/quickstart.md) and use `rp --help` for
the guided command interface. Package CLIs such as `research-io`,
`research-bids`, and `python -m research_platform.analysis.cli` are advanced,
package-specific interfaces.

[`ADR-0022`](decisions/ADR-0022-headline-hpc-execution-contract.md) records a
future conditional acceptance contract for one narrow synthetic SLURM
lifecycle. Its implementation is incomplete, no live cluster has been
validated, and it does not change any status below. HPC remains plan-first and
either **Plan/validation only** or **Experimental or external-runtime** until
all implementation, fake-remote, live-cluster, and dedicated claim-promotion
gates pass.

The coordinated source-package version is `0.1.0a1` across the eight
`packages/research-*` distributions. Versions in the `project-example` and
`project-template` scaffold `pyproject.toml` files are independent scaffold
metadata, not part of that coordinated source-package version. The three app
roots remain **Scaffold only** README-level ownership and extension boundaries.
A private or development checkout may contain placeholder app metadata or
files, while a curated public export may retain only each root README. Neither
directory presence nor placeholder content establishes implementation,
support, or an implemented runtime product.

## How to read this matrix

A plan is useful evidence about configuration and safety, but it is not evidence
that an external tool, dataset, or cluster has executed. Likewise, package-level
integration tests are real implementation evidence without automatically making
a public project overlay runnable. Status moves to **Runnable locally** only when
the public repository also gains a documented, checked-in project-level path and
an executable verification for that path.
